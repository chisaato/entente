# 响应压缩归属 TLS 绑定

原站点只在部分域名开启 `zstd gzip`。listener 级压缩会意外改变其他站点行为，而为此引入通用中间件框架超出当前需要，因此把可选 `compression` 放在 YAML 的 TLS 绑定上：同一绑定内的站点共享压缩配置，不同绑定可复用证书但保持各自行为。没有配置的绑定和兜底链不压缩，label 不能开启压缩。

编码列表及其顺序、最小长度、精确 MIME 列表必须显式给出。只支持 `zstd` / `gzip`；拒绝未知或重复编码、缺失长度及通配 MIME，避免 Envoy 静默忽略通配匹配。按配置顺序构造 router 前的 compressor 过滤器，首选编码在客户端偏好相同时优先。

这不是 Caddy `encode` 的逐字节兼容实现：Envoy 只匹配精确 MIME，不能照搬 `text/*` 等通配列表。迁移方必须枚举需要的类型并显式设置阈值；未知类型不压缩，不能为了接近旧行为把压缩扩展到所有站点。
