# 本地 PEM 文件是与 KV 互斥的证书来源

不跑 OpenBao 时，可以从本地 PEM 读证书（例如 acme.sh 写到磁盘的 `fullchain.pem` / `key.pem`），读入内存后走同一条 ADS SDS 流。文件来源不发 HTTP，也不连接 OpenBao。KV 来源的行为仍是 ADR-0014。两种来源可以列在同一份 `secrets` 里，但每个 secret 只能有一种：`file` 与任一 KV 字段同时出现则拒绝，两个都没有也拒绝。`name` 在整份列表里唯一，和来源无关。

`file.certificate_chain` 和 `file.private_key` 必填，且必须是绝对路径（ADR-0002）。不在配置里写轮询间隔或防抖时间，那些是代码常量。只有存在 KV 来源时 `openbao` 才必填；纯 file 配置不创建 HTTP 客户端。配了 `openbao` 但一个 secret 都没有，仍然是配置错误。文件路径跟 `secrets` 列表一样可以热重载；`openbao.*` 仍需重启。

## Consequences

启动后立刻读，不等文件系统事件。监听的是两个文件的父目录，所以原地覆盖和「写入临时文件再 rename」都能看见；同一目录只监听一次。相关事件按 250ms 合并后再读，避免证书链和私钥各写一次就读到半对新。父目录还不存在时不能只等 inotify：读取或监听失败后按 1s→30s 退避重试，目录或文件后出现就会补上监听并重新读取。监听正常时每 30s 也重读一次，防止目录被整个替换后盯着旧 inode。

两个文件都要通过 `tls.X509KeyPair` 才成对下发；只换了证书、私钥还是旧的，视为失败。失败语义见 ADR-0015。日志只写 secret 名、路径和固定错误，不写 PEM。证书链或私钥字节变了，快照哈希才变；时间戳变了但内容相同，不推新版本。从配置里删掉该 secret 会立刻从快照移除。同名 secret 换路径时，新文件还没读成功就继续下发上一份有效内容。
